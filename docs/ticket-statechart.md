# The ticket statechart

A ticket has one state machine, drawn here from its tables and never by hand.
It is a hierarchical statechart: a stage can hold sub-states, and a move that leaves the stage is legal from each of them.
The tables are `core/machines/tables/ticket.tsv` (machine 0 of the state-machine plan), `delivering.tsv` (machine 20) and `proving.tsv` (the proof run that fills `proving`).
This slice is report-only: no script writes a move yet, and the engine never changes a record.

- **Seven stages**, **twenty edges** and **seventeen events** (`close` leaves `released`, `building`, `delivering.batched` and `delivering.live`): `file`, `approve`, `start`, `reclaim`, `claim-done` (twice: from building, and again from proving with another head), `prove-fail`, `prove-pass`, `bypass`, `answer`, `relayed` (a Recon's findings reached the owner, from proving), `new-head`, `refuse`, `release`, `revert-released`, `close` and `drop`.
- **`delivering`** holds seven sub-states, `queued`, `resolving`, `rebased`, `gated`, `batched`, `live` and `joining`, and the two ends `on-main` and `returned`. It has twelve events.
- **`proving`** holds the proof run: `planned`, `writing`, `running`, `judged`, `reviewing`, `waiting` and the ends `sealed`, `failed` and `aborted`.
- A stage is never `unknown`. Who owes the next move (the wait) and how the ticket fares (the health) are separate words, listed in `core/machines/maps/ticket-words.tsv`.
- The proof run's event `settle` is `answer` in the plan. The ticket's own move `answer` leaves `proving` from every sub-state, so the two names would collide on `proving.waiting`.

## Ask the engine

```
bin/jg-machine.sh events ticket                          # the sixteen moves
bin/jg-machine.sh edge-check ticket proving.running building   # legal, from any sub-state
bin/jg-machine.sh diagram ticket --mermaid                # the diagram above
bin/jg-machine.sh word ticket-words task rework          # building, worker, red
core/machines/ticket-corpus.sh > corpus.tsv && bin/jg-machine.sh replay ticket-words corpus.tsv
bin/jg-machine.sh records ticket-words core/machines/corpus/pr-records.tsv
```

## Where an older word lands

`core/machines/maps/ticket-words.tsv` gives every word of the eleven older tables, of the status logs and of the shadow log a target, a wait and a health.
`replay` fails and names each word that has none.
The `rule` lines decide the pull request style: the pull request's state and where the work is (main, the trunk, or nowhere) give the stage, first match wins.
`core/machines/corpus/pr-records.tsv` holds the 21 live records of that style with the target each must get.
