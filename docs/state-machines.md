# State machines

This page is the one place a fix lane finds a machine's table, the command that reads it, and an example.
A machine is a record family whose state is spread over several files and scripts, such as a status log, a landing file, or an inbox.
Its table says which states exist, which moves are legal, and which script performs each move.
The records stay the truth, and the command only reads them.

## Find the machine

Each row is one table in `core/machines/tables/`, with the record it holds and the one file that owns it.
The `Ask` column is the command that prints a record's state and its legal moves.

## Ask a machine

```sh
bin/jg-machine.sh next <machine> <id>
```

The output lists the record's state and each legal move with its writer, command, and guard.
[`core/machines/README.md`](../core/machines/README.md) owns the table format, the commands, and the exit codes.

## Ask whether a change is live

```sh
bin/jg-machine.sh show delivery <change-id>
```

A change that ships behind a switch has a row in `core/machines/changes.tsv`, and the answer is `in-homes-off` until the switch is on.
The state machine slices `sm-s1a-engine` to `sm-s12-enforce` are registered there, behind `config/machine-view` and `config/machine-enforce`.
[`core/machines/README.md`](../core/machines/README.md) owns the delivery states and the rule for a report.

## Fix a bad state

When a bug is a state that should not exist, follow [Make the implicit state machine explicit](../.agents/skills/diagnostic-reasoning/SKILL.md#make-the-implicit-state-machine-explicit).
Write the table in `core/machines/tables/`, replay the record that shows the bug with `bin/jg-machine.sh check <machine> --corpus <file>`, fix it at the machine's one owner, and add a test for the move.
