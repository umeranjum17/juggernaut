# How state is managed

Everything the fleet owes is an **item**: one thing someone must do, by a deadline. A ticket's lane is an item. So are an owner's question, a reply to his note, a steer, an alert, a landing and a cleanup.

Items live in one file per machine: the main home's `state/item-store/fleet.db`. Every home on the machine writes and reads that same file; `jg-item where` prints it. Nobody edits an item. Every change is a **move** added to a log, and the item is what the log adds up to. There are five moves: **open** (something is owed), **note** (add text), **hand** (give it to someone else, with a reason and a new deadline), **climb** (the deadline passed, so it goes one step up) and **close** (done with a proof, or dropped with a reason). An item is **open**, **done** or **dropped**. Nothing is ever deleted; a correction is a new item that points at the old one.

Every move records who made it and when. `jg-item` takes both from where it runs and from the machine's clock, never from an argument. That stops mistakes, not a deliberate writer, so at every tick the store checks each new owner answer, each bridge's move and each of its own drops against the record it claims, and opens a security item on Main for any that does not match. Every 15 minutes it re-applies the whole log to a fresh copy of the rules; a move the rules would refuse, or an item that does not match its moves, opens an alert on Main. If the machine's clock jumps, the tick moves each open deadline by exactly how far the clock moved since that deadline was set, and tells Main. Every home's watcher runs `jg-item tick` every 5 minutes; the first one to find the last tick more than 4 minutes old runs it and the others return at once, so the store ticks once per machine, and it still ticks when Main's watcher stops (then Main-down climbs to the owner on time). Each re-check's seconds go to `tick.log`; a re-check over 10 seconds prints one line, because the watcher stops a check at 30 seconds.

Every open item has a **holder** and a **deadline**. When the deadline passes, it climbs one step up one ladder: the **worker**, its **lead**, **Main**, the **owner**. A wait goes first to whoever its writer named (`wait=lead`, `wait=outside` with a date, `waits-for: <ticket>`); only Main may turn a wait into a question for the owner. Only questions only the owner can answer, security and Main's own supervision going down ever reach him.

Each project has one **policy** record: its delivery mode, and its leash in one word, **tight**, **standard** or **loose**. With yolo on (loose), the machine merges, lands and releases. With yolo off, a project on its own local trunk lands by itself and is released on the owner's word (standard); any other project waits for his one word to land or merge, and that word carries the release (tight). His word covers what he was shown: one pull request, or the head of one release pull request. If more is pushed after his yes, he is asked again. Only his own words change a policy: his message that names the change, or his yes to a question that carries the new version.

Every arrival (a status line, a chat message, a CI run) is written with its own id, once per item it touches, so writing it twice changes nothing: every write names that id with `--source`, and the store refuses a write without one (only the tick's own moves have none). An adapter whose write is refused, or fails in any other way, opens one intake item on Main that names the refusal or the error, so nothing is lost.

Every item about a ticket's work has the ticket's id as its subject, and its key says which home and which task or step it belongs to: `work:<home>/<task>`, `wait:<home>/<task>#<wait key>`, `land:<home>/<ticket>@<head>`, `merge:<home>/<ticket>@<pull request>`, `release:<project>@<pull request>`, `question:<home>/<ticket>`, and `question:land:`, `question:merge:` or `question:release:` followed by the step's own key for the owner's word on that exact step. A release and its question have `<project>@<pull request>` as their subject, because a release belongs to a project, not to one ticket. `jg-item key <kind> --task <task>` prints the key, the subject and the project (read from the task's record), and the store refuses an open whose key does not have its kind's shape. Work, a landing and a merge name their project, whose policy decides them. `core/item-store/keys.py` is the whole table. A blocker names the step it holds back, and closes when that step closes. A finished lane's cleanup runs by itself through the guarded cleanup script; if the script refuses, the item stays with the lead with the reason.

A wake reads only what is new: `jg-item pages <me>` lists the pages past your place, one line per item, at most 200 lines, and ends with a count line; `jg-item ack <me> <seq>` moves your place. If you stop before you ack, the next read shows the same lines again. To see everything, read the board (`jg-item board`: every open item, its holder and deadline) or the digest (`jg-item digest`: what is late, per holder). The owner's chat reads `jg-item pages owner`: what climbs to him (his questions, security, Main-down). A turn summary, a reply or a voice message is not an item; each keeps its own sent log.
