# Wake bus cursor under a killed render

Wake bus cursor under a killed render: run `done-done run wake-cursor-kill` (`bash journeys/wake-cursor-kill.sh`); a throwaway server and home, a real `bin/jg-wake-bus.sh raise` whose render is parked and killed (kill -9) after it read the wake stream, then restarted; the transcript shows the killed wake, an earlier wake and three ordinary wakes each delivered exactly once, and fails on any other count (the old code delivers the killed wake 0 times); its last step sets the cursor past both stream ends (`JG_WAKE` 6347, `JG_INBOX` 1630) and shows both streams read again from the start, a waiting steer kept and a handled one settled (the old code settles the waiting steer and keeps the handled one). A message the server refuses for one render holds the cursor before it, for two renders still holds it, and on the third the render keeps it (stream, sequence and the server's own words) on `state/bus/wake-render.dead.jsonl` and reads past it, so the cursor advances and the wake raised after it still arrives (the old code pins the cursor before that message forever). `bash tests/jg-wake-queue-live.test.sh` holds the same cases.
