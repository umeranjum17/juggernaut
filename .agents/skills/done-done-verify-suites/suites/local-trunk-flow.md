# Local trunk flow (projects registered local-trunk only; direct-PR, no-mistakes and local-only projects are proved untouched by `tests/jg-trunk-scope.test.sh`, which the same journey runs)

Local trunk flow (projects registered local-trunk only; direct-PR, no-mistakes and local-only projects are proved untouched by `tests/jg-trunk-scope.test.sh`, which the same journey runs): run `done-done run trunk-landing` (it invokes `bash journeys/trunk-landing.sh`, which runs `tests/jg-trunk.test.sh` and its `-live`, `-gate`, `-queue`, `-retry` and `-verify` parts); the real `bin/jg-trunk.sh`, `bin/jg-trunk-live-home.sh`, `core/trunk-landing` and the shared landing gates run over real git repositories, a bare origin and a recording forge, and prove a done one-commit lane lands by itself and never goes live, the lander rebases a lane on a moved tip by itself, a lane lands only with its whole proof at its head (completion receipt, approved merge-card evidence, sealed done-done run) and both its done and the landing refuse before starting on any missing input, while the owner signature never blocks a landing (it is recorded after it), a refusal that only needs time is tried again by itself and a lane whose red trunk cleared lands with no hand step even while every check finds another landing running, while one whose red still holds stays waiting and never restarts itself in a loop (that case alone: `done-done run wait-refusal-retry`), three lanes ready at once land in order with no human step while a red one is refused, two or more ready lanes land as one stack (one gate over their changed files, one trunk move, a conflicting lane dropped, a red stack halved until only its guilty lane is returned, a red the whole suite finds after the stack traced to its one commit and reverted), a commit that passes the landing check and breaks the whole suite is reverted by itself after the landing and its ticket is told, live and release refuse without the captain's recorded word, unsafe landings (a second commit, a conflict naming its paths, a failing check, a failing lint, an owner-guard hit, a commit with no ticket reference, an open linked decision, away mode, a protected path, a red trunk, a trunk a lane moved) refuse and leave the trunk unchanged, each open captain call changes behaviour only through `config/trunk-policy`, a landing keeps the home on the last fully green commit until `verify` passes (a verify finishes and moves the pin while a long landing is still in its gate, three queued verifies run only the newest, a lane whose tip moved during its gate is rebased and gated again, a verify whose only failures its parent already had moves the pin, a verify whose only failures pass on their one rerun moves the pin and files one fix row per flaky test, and verify judges every change since the trunk's release base, the set CI maps for the release), the release is one pull request from the trunk itself with no release branch, a hand write, rewind, force or delete of the trunk is refused by the project hook, the next trunk version is cut only after the release PR merged and the old trunk is deleted unforced (remote, local, clean worktrees) only when its release is proved on main and every hotfix is carried, a copy with unlanded work being kept and listed, landing raises the same merged event as the local merge, the landing check cleans a landed task up unforced, and a red CI pins the home back to the last green commit (screen: none).
