# Local trunk flow (projects registered local-trunk only; direct-PR, no-mistakes and local-only projects are proved untouched by `tests/jg-trunk-scope.test.sh`, which the same journey runs)

Local trunk flow (projects registered local-trunk only; direct-PR, no-mistakes and local-only projects are proved untouched by `tests/jg-trunk-scope.test.sh`, which the same journey runs): run `done-done run trunk-landing` (it invokes `bash journeys/trunk-landing.sh`, which runs `tests/jg-trunk.test.sh` and its `-live`, `-gate`, `-queue`, `-retry` and `-verify` parts); the real `bin/jg-trunk.sh`, `bin/jg-trunk-live-home.sh`, `core/trunk-landing` and the shared landing gates run over real git repositories, a bare origin and a recording forge, and prove a done one-commit lane lands by itself and never goes live, the lander rebases a lane on a moved tip by itself, a lane lands only with its whole proof at its head (completion receipt, approved merge-card evidence, sealed done-done run) and both its done and the landing refuse before starting on any missing input, while the owner signature never blocks a landing (it is recorded after it), a refusal that only needs time is tried again by itself and a lane whose wait cleared (away mode ended) lands with no hand step even while every check finds another landing running, while one whose wait still holds stays waiting and never restarts itself in a loop (that case alone: `done-done run wait-refusal-retry`), three lanes ready at once land in order with no human step while a red one is refused, two or more ready lanes land as one stack (one gate over their changed files, one trunk move, a conflicting lane dropped, a red stack halved until only its guilty lane is returned, a red a hand-run verify finds after the stack traced to its one commit and reverted), a landing moves no green pin and starts no whole-suite run (a whole-suite shard over its time budget stops no landing); each tick starts the line's verify while the tip is above the pin, one at a time, and only a green verify moves the pin: two landed changes that pass alone and break together are traced by the verify, the second is reverted, `line-red` is raised, the pin and the go-live stay put, and a tip a verify ended on is not verified again, while the no-green alarm is quiet while a verify runs, a commit that passes the landing check and breaks the whole suite is reverted when a hand-run verify finds it and its ticket is told, live and release refuse without the captain's recorded word, unsafe landings (a second commit, a conflict naming its paths, a failing check, a failing lint, an owner-guard hit, a commit with no ticket reference, an open linked decision, away mode, a protected path, a trunk a lane moved) refuse and leave the trunk unchanged, a red trunk never stops a landing, each open captain call changes behaviour only through `config/trunk-policy`, a red a hand-run `verify` finds takes the green pin back below it so the home never goes live on it (a verify finishes and moves the pin while a long landing is still in its gate, three queued verifies run only the newest, a lane whose tip moved during its gate is rebased and gated again, a verify whose only failures its parent already had moves the pin, a verify whose only failures pass on their one rerun moves the pin and files one fix row per flaky test, and verify judges every change since the trunk's release base, the set CI maps for the release), the release is one pull request from the trunk itself with no release branch, a hand write, rewind, force or delete of the trunk is refused by the project hook, the next trunk version is cut only after the release PR merged and the old trunk is deleted unforced (remote, local, clean worktrees) only when its release is proved on main and every hotfix is carried, a copy with unlanded work being kept and listed, landing raises the same merged event as the local merge, the landing check cleans a landed task up unforced, and a red CI pins the home back to the last green commit (screen: none).

A guarded home live move: run `bash tests/jg-trunk-live-home.test.sh` and `bash tests/jg-update-local-base.test.sh`; the single-home and fleet callers advance the recorded guard tip with HEAD, and a refused ref move leaves the guarded home clean at its old tip (screen: none).

The same trunk-landing journey checks that a final refusal and an exhausted retry reach the lane's inbox once, add a ticket note, and put the task in rework.

A legacy trunk with no version row: `bash tests/jg-trunk-release-open-pr.test.sh` drives the release retry, reconstructs the merge base from the default branch, and checks the recorded row (screen: none).

Diverged trunk recovery: the same journey creates eight recorded commits and one divergent actual commit, reports both tips, prepares a merge, refuses missing proof and a third ref, and lands only the exact proved merge while retaining both histories (screen: none).

The publish step under the standing release word: run `bash tests/jg-trunk-publish.test.sh` (the same journey runs it); the green pin is pushed once the trunk holds enough, a candidate after a red is pushed once for each new tip, and a green result on it moves the pin (screen: none).

yolo asked once, at `gated`: `bash tests/jg-trunk-release-merge-first.test.sh` (the same journey runs it; T5 and T6) drives the real landing check, `bin/jg-trunk.sh` and the registered merge check: with yolo on a lane of the style `local` lands, goes live, is published and merged into main with no word and no waiver recorded; with yolo off it waits at `gated`, and one word (`merge=approved`) carries it to main with no second word (screen: none).

The carry check of an old trunk: `bash tests/jg-trunk-carry.test.sh` (the same journey runs it) drives the real `jg-trunk.sh retire` over a release merged by rebase: an empty commit and a commit the current trunk holds by patch under another id are not uncarried and the old trunk is cleaned up, while a real hotfix still keeps it and is named; `tests/jg-trunk-release-open-pr.test.sh` runs the same check in the release proof (screen: none).
