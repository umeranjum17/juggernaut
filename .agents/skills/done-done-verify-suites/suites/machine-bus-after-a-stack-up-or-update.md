# Machine bus after a stack up or update

Machine bus after a stack up or update: run `done-done run bus-machine-service` (which runs `tests/jg-bus-machine-service.test.sh`): in a lab with its own random port, store and fake `systemctl` (never 4222 or the machine service), one home owns the unit; other homes' `install-service` and `unit nats` (what `jg-stack.sh up` writes the unit from) only add their account and have the server reload it, leaving the owner's unit file and `bus.conf` byte-identical with no restart, and every home passes `ensure`; a home past the caps is refused naming the owner; a temp or worktree test home is refused by the machine's real registry, which stays byte-identical, and the registry `JG_BUS_HOMES` names holds it instead; a home the owner's registry names - one that keeps no registry of its own - presents that recorded name from every client (`account`, and the wake bus and key-value clients through `login`), creates its stream and round-trips one message, while a name the accounts file does not hold is still refused with `Authorization Violation`, the way production refused the hashed name; a stream check (`jg-bus stream`) from a home whose password begins with a dash logs in through a 0600 `state/bus/nats-context.json`, and the lab's argv-recording `nats` shows no call any bus command made carried `--password` or any home's password; 21 accounts get caps for 21 reservations plus headroom and a real server starts on them; the 384Mb incident cap is refused by `jg-bus check-limits` and reproduces `insufficient memory resources` on a real server; and `bin/jg-bus.sh status` reads each service's own unit state from the manager, so active units read up, one stopped unit reads down alone while the others stay up, and a probe that cannot ask the manager reports `unknown`, never down. The same journey runs `tests/jg-stack-owner.test.sh`: the real `bin/jg-stack.sh up` with a stand-in bus command and a logging `systemctl` installs, enables, starts and provisions dapr for the owner, retires the old ntfy and consumer wiring once, and for a home that does not own the unit installs, starts and provisions none of it and names the owner. Live: `bin/jg-bus.sh check-limits state/bus/bus.conf` on the owner prints `limits: ok`. The test stops its lab servers in every exit and signal trap, and runs `bin/jg-bus-reap.sh` first (it stops a `jg-bus-machine` nats-server whose config directory is gone, by pid and config path, and never a live lab or a server outside such a directory; `--dry-run` lists them): SIGTERM the test or the journey's process group mid-run and `ps` shows no lab server left.
