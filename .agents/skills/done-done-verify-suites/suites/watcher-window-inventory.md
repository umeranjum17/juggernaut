# Watcher window inventory (Go)

Watcher window inventory (Go): run `bash tests/jg-watch-inventory.test.sh` (or `done-done run -- bash tests/jg-watch-inventory.test.sh` with the log written into `$DONE_DONE_EVIDENCE_ROOT`); it replays a corpus of `state/<id>.meta` records through `bin/jg-watch-core.sh` and the shell reader it replaced and requires identical watched rows, identical order and identical kind, backend and harness answers after every record, fails two corrupted controls (one answer, one row order), then runs a real `bin/jg-watch.sh` cycle over a throwaway home with a logging wrapper around the Go command and requires that cycle to read its inventory there and deliver its wake; then runs the real watcher over an empty home and requires one cycle in 9 seconds with a 30 second idle period against at least 3 at the poll period, and over a home with a check that burns CPU requires that check's CPU seconds in `state/.watch-cost` and, over its budget, named in the triage log (`core/watch/cmd/jg-watch-core/interval.go` owns the idle period and the cost row). `core/watch/README.md` owns the port record and the decisions this slice made; `core/watch/cmd/jg-watch-core/main.go` the field rules. Live read-only: `JG_STATE_OVERRIDE=<home>/state bin/jg-watch-core.sh inventory <home>/state/*.meta` prints the rows the watcher itself reads, and the watcher's own stderr names `window inventory read failed` when it cannot (screen: none).
