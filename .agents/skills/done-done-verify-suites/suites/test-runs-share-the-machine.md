# Test runs share the machine

Test runs share the machine: run `done-done run -- bash tests/jg-test-run.test.sh` with the log written into `$DONE_DONE_EVIDENCE_ROOT`; the real `bin/jg-test-run.sh` with `machine_runs_max=1` makes a second run print that it waits for a test-run slot, naming the runner that holds it, and start its script only after that run ends, while a run started inside the admitted run, even one with a cleared environment, never waits; a test script that moves HOME still reports the caller's own Go build cache from `go env GOCACHE`.
a run of the trunk itself (`JG_TRUNK_GATE_OUTPUT`) starts at once on its own reserved slot while lane runs hold every general slot.
The cases fail on a runner without the slots or the shared cache (screen: none).
a burst of six runs started at once never has more than the slot limit (2 or 3 by default, one per 16 cpus) testing at once, every script runs at nice 10 or lower priority, and `load.tsv` in the slot directory holds the load1 and CPU pressure at each slot grant and release (`test_a_burst_of_runs_caps_at_the_slot_limit_under_nice_and_records_the_load`).
a run puts all its scratch on disk, never /tmp (RAM): with no `TMPDIR` set, the run, its slot directory and every script get `TMPDIR` under the cache home's `jg-scratch`, a caller's own `TMPDIR` is kept, and `jg-mem-gate.sh` gives a heavy job the same root plus a matching JVM tmpdir (`test_a_run_writes_its_scratch_on_disk_and_keeps_a_callers_tmpdir` and `core/host-memory/tests/jg-mem-gate.test.sh`).
