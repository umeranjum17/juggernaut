# Lanes on the Beads store

Lanes on the Beads store: the same run proves a real `bin/jg-spawn.sh`, `--relaunch` and `bin/jg-teardown.sh` on a Beads home move the row's assignee and `metadata.agent` with the task record, a spawn on a row another lane holds refuses with exit 13, and a close or retain that loses the race leaves the row with the lane that won.
The same run drives the spawn, teardown and bootstrap transitions through `bin/jg-backlog-transition-lib.sh` on both stores and requires one answer, and a real second writer between the read and the write gets a stale-write refusal that leaves the row alone.
The same run drives `bin/jg-captain-hold.sh` hold, answer, release, keyed answers, reconcile and complete on both stores and requires one answer and one exit status for each step and each refusal, and a home with no store refuses instead of reading as not held.
It then drives `blocking`, `design-card` and `design-pick` on both stores, and on Beads proves an edge alone stops linked work in either direction, the design row is labelled `decision`, its ticket leaves `ready` until the pick, and a store that cannot answer exits 2.
`bash tests/jg-beads-native-hold.test.sh` with the same pins proves `bin/jg-captain-hold.sh` never starts `bd` itself, on a real store, and that an attested old id reaches its row through the provider's `show`.
The same run drives `bin/jg-pr-merge.sh`, `core/merge-on-green/merge-on-green.sh`, `bin/jg-merge-local.sh` and `bin/jg-ci-rerun.sh` on both stores against a recorded forge and requires the same story: a held PR, a linked PR, a PR behind a Beads `blocks` edge alone and a held local branch refuse, a released PR, a watcher merge and a local landing go through, the shipped close moves the row, and a store that cannot be read refuses both merges without reaching the forge.
