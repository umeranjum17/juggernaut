# Large check or status text never ends supervision

The same watcher suite exercises self-filed repair dispatch.
Three consecutive failures create a repair, and the dispatcher briefs and submits it to spawn on the standing approval from jg-m7h.
It refuses a repair while the standing approval is missing and gives a human-filed ticket with the same title no automatic approval.

Large check or status text never ends supervision: run `done-done run -- bash tests/jg-watch-large-check-output.test.sh` with the log written into `$DONE_DONE_EVIDENCE_ROOT`; the real watcher on a throwaway home with registered checks shows a 3,000,000-byte check result wake with a bounded reason that names the file holding the full output while the next check still wakes, a check whose capture cannot start is logged and skipped with the watcher still running, and the real ready-work reader takes a 3,000,000-byte priority listing without `Argument list too long` (screen: none). Before the fix the first case fails with `jg-wake-bus.sh: Argument list too long`.
