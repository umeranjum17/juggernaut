# Watcher own-queue observation on the bus

Watcher own-queue observation on the bus: run `done-done run wake-watcher` (which runs `bash tests/jg-wake-watcher.test.sh`); it first drives real quick sequential CLI raises, a concurrent burst under a future high-water floor (equal/backward-clock branch), a later CLI settle, exact numeric/identity uniqueness through the 53-bit limit, offline publication identity, historical sequence ties and corrupt/exhausted-state refusal, then replays 123 recorded `JG_WAKE` events (`tests/fixtures/wake-recorded/events.jsonl`; `JG_WAKE_REPLAY_CORPUS=<export>` replays a larger one, 241 events were run clean) through the Go fold (`jg-bus watcher replay`) and the shell reader it replaced and requires identical rows, oldest row and host-memory row after each event, fails a corrupted control, then on a throwaway accounts server proves the `wake-watcher` consumer's acknowledged counter rising on real raises, the fold equal to `state/.wake-queue`, an acknowledgement dropping its row, a restart and a lost fold recovered, and the real watcher cycle re-delivering a stalled row with the queue file unreadable. Live on this machine: `bin/jg-bus.sh probe wake-watcher` before and after a real wake on a home whose stack is up (`bin/jg-stack.sh up` installs the service); `bin/jg-bus.sh watcher oldest` prints the row the watcher would re-deliver and its idle seconds. `core/bus/cmd/jg-bus/watcher.go` owns the verbs; `docs/bus-service.md` "The wake watcher" the contract.
