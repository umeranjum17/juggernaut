# Beads ticket adapter

Beads ticket adapter: run `JG_BEADS_TEST_BD=$(which bd) JG_BEADS_TEST_DOLT=$(which dolt) done-done run -- bash tests/jg-ticket-adapter.test.sh` (it copies its output and both conformance logs into done-done's evidence folder) to drive the real `bin/jg-ticket-adapter.py` the way the board does, one JSON request per call, on a throwaway embedded Beads store; it proves the single-store interface returns bd's own row and leaves closed rows out; in two isolated fleet homes (beside a home that names no store and a home that is gone, which are skipped) it reads each store with one query, hands a client that names no page size the whole fleet in one page, gives a ticket the same rev from the list and from a get, and derives the four board columns from gates, worker records, ready rows and recent closes, shows each project, routes edits to their store, paginates and reports a failed home, an update is a patch that keeps a label bd alone wrote, a write made by hand gives a conflict, a repeated op_id writes once and a reused op_id is refused, history names the actor and the changed fields with the comment in order, and an unreadable store is an error and never an empty list; it also runs the vendored interface conformance script unmodified (17 of 18, check 2 reads bd-sorted key order) and through its documented order-insensitive exception (18 of 18) (screen: none).
