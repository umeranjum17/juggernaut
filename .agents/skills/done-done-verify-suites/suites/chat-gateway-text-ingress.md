# Chat gateway text ingress

Chat gateway text ingress: run `done-done run -- bash tests/jg-bus-gateway.test.sh` (log into `$DONE_DONE_EVIDENCE_ROOT`); a fake Telegram Bot API, a fake Dapr sidecar and the real `bin/jg-inbox.sh` prove an allowlisted text is one note and one `inbound` event, a replay is no second note, a stranger, a group and a bot are dropped and counted, a group-readable token file is refused, and the bot token is in no file the run wrote. Chat gateway answers (same command, `TestGatewayAnswers`): a note then `jg-inbox.sh reply` is exactly one `sendMessage` threaded on the owner's message, a 429 is waited out, an answer over 4096 characters is split, and a restart sends nothing twice. Chat gateway pairing (`TestGatewayPairAndStatus`): with no token file the gateway is silently off, the first person to send the code becomes the owner in `config/captain-channel`, and `gateway status` asks `getMe`. Chat gateway inbound media (same command, `TestGatewayMedia`): a photo (largest size), a document and a voice note are stored once by hash under `state/captain-chat/media/<day>/` (folders 0700, files 0600), named in the note as `[file <kind> <path> <size> <mime>]` and in the `inbound` event's `media` field; a file over 20 MB is not fetched and is refused in the chat; a stranger's file is never fetched; old events still replay with no parity difference; files older than `chat-media-days` are pruned. Chat gateway token handling (`TestGatewaySecret`, the helpers of `gateway setup`): a token is read on a pseudo-terminal with echo off (a control shows echo works once restored), a pipe is read as it is, and a stored token file is mode 600 and replaces a looser old one. Chat gateway bring-your-own-bot setup (`TestGatewaySetup`): `gateway setup` reads the token on a pseudo-terminal that does not echo it, `getMe` names the bot, the token file is mode 600, the first private message with the code records the owner, Enter alone keeps a stored token, a malformed or refused token is saved nowhere, and the token is in no file or output. Chat gateway outbound media (same command, `TestGatewayOutboundMedia`): a reply that names files is sent as multipart `sendPhoto`, `sendDocument` or `sendMediaGroup` streamed from disk, threaded on the owner's message, with the text as the caption; a picture Telegram refuses is sent again as a document; `config/x.token`, a symlink to it, `.env`, a file over 50 MB and a vanished file are never sent and are named in a text reply; a restart sends nothing twice; the bot token is in no file the run wrote. Chat gateway outbound events (same command, `TestGatewayConsumer` and `TestGatewayFallback`): card, outcome, alert and digest events go to the owner as one `sendMessage` each and a probe goes nowhere, a redelivery sends nothing twice, a failing send is tried again, a blocked bot is tried once and named undelivered, a refused Dapr publish still reaches the chat in-process and a failure of both is named in the undelivered record; the bot token is in no file the run wrote. Chat gateway card replies (same command, `TestGatewayCardReply`): a card carries the reply line, the owner's text reply to it is published once as that card's answer, and with Dapr down the board route takes it. Chat gateway receipts (same command, `TestGatewayReceipt`): a filed note gets one `setMessageReaction` on the owner's own message; a refused reaction still leaves the note and its `inbound` event; `/status` (and `/status@botname`) is one threaded `sendMessage` from the gateway with no note, event or reaction, a stranger's `/status` is dropped and counted, and the bot token is in no file the run wrote. Chat gateway voice notes (same command, `TestGatewayTranscript`): with a real `ffmpeg` and engine scripts, a voice note and a round video note put `transcript: <words>` under their file line and in the `inbound` event, the 👀 reaction is sent before the engine finishes, audio past `chat-transcribe-max-seconds` is cut and marked, a timeout, a missing engine, a failing engine, an unreadable file and a silent wav whose engine prints only a made-up silence phrase (`Thanks for watching!`) each file the note with `transcript: unavailable (<reason>)` (the last reads `no speech found`; `TestInventedSilence` holds the filter rules: only known phrases or one short phrase looped are dropped, longer speech stays), with no engine the note is unchanged, and no words or engine output are in the log; with `JG_TEST_STT_HOME` (a home where `bin/jg-chat-transcribe.sh setup` ran) and `JG_TEST_STT_WAV` (a recording of speech) set, the same test also runs the installed engine through the gateway and logs only the word count. Chat gateway design options (same command, `TestGatewayOptions`; `bash tests/jg-inbox.test.sh` covers the `reply --option` script side): `jg-inbox.sh reply --option A --option B --attach pic` sends the picture, then one `sendMessage` with a two-button inline keyboard whose callback data is short and opaque; the owner's tap is answered at once, marks the message with `Picked: <label>`, and files exactly one note `[chat telegram <chat>:<message>]` plus `pick: <label> (<set id>)`; a second tap, a stranger's tap, an unknown or stale set and a replayed tap are answered and file nothing; with `--allow-change` a tap on another button files a second pick; the bot token is in no file the run wrote. Chat gateway typing indicator (same command, `TestGatewayTypingIndicator` and `TestGatewayTypingUntilReply`): the chat gets `sendChatAction` `typing` from the moment a note is filed, repeated while it is open, one indicator per chat however many notes are open, stopped at once by `jg-inbox.sh reply`, by the hard cap and by shutdown; a refused action is logged once without the token and never stops the note or its reply. Chat gateway poll health (same command, `TestGatewayPollHealth`): the real `gateway serve` loop in a child process against a fake Bot API whose `getUpdates` answers 502 turns `gateway status --row` pending (`the gateway is running but its last N polls failed`) after 3 failed polls, `state/captain-chat/telegram.poll` holds the last good poll, the failures in a row, the last attempt and the redacted reason, and the first good poll resets the failures and the row (the heartbeat moves only after a successful poll). For a live pass, `bin/jg-bus.sh gateway --once` against a local fake Bot API in a scratch home (screen: none).
