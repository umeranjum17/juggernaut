# A test never takes the machine

A test never takes the machine: run `done-done run test-unit-isolation` (`bash journeys/test-unit-isolation.sh`, which runs `tests/jg-remote-squad-lead-lifecycle-e2e.test.sh`, `core/sentinel/tests/jg-sentinel-install.test.sh` and `tests/jg-trunk-queue.test.sh` and writes its log and `steps.json` into the run's folder). It proves that a remote squad lead's code-root update, run on a simulated host with its own account (stub `systemctl` and `systemd-run`), fast-forwards the remote home while installing no unit, no sentinel copy and no systemd change for the throw-away root; that the sentinel install refuses a throw-away home (one under a temp root or a `jg-test-run.*` folder) for an account's own unit dir, and, by a dry run, for this account's real one (`bin/jg-lab-home-lib.sh`); that a post-landing job the landing check detaches, still hung when the suite ends, is stopped with its process group by the suite's cleanup; and that this machine's real `jg-sentinel.service` has the same mtime and bytes after the run as before (screen: none).
