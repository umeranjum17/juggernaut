# Ticket move command

Ticket move command: run `done-done run ticket-move` (`bash tests/jg-move.test.sh`, which writes its log into the run's folder); in a test home with a copy of the ticket tables, the real `bin/jg-move.sh <ticket> <event>` exits 1 on an event the ticket's stage does not have (`prove-pass` from `building`, an unknown event, `start` for a ticket in no stage), names the legal events and writes no line to `data/moves.log`, and a legal move (`claim-done`, then `file` for a new ticket) appends exactly one line with the ticket, the stage before, the event and the stage after; and in shadow (`--shadow`) the real status append (`bin/jg-lavish-guard.sh --append`) makes `claim-done` for a done line and the real backlog close makes `close`, each one legal move and no line in `data/machine-shadow.log`, while an illegal done line adds one shadow line and still succeeds; with `ticket` listed in `config/machine-enforce` the same illegal done line and the same illegal close are refused, nothing is written and the log line reads `refused`, and deleting that file's line returns them to shadow; it reads only generated fixtures (screen: none).

A move the ticket already made (a pair listed `settled` in `core/machines/maps/ticket-traffic.tsv`, such as `start` while the ticket reads building) exits 0 and writes no move line and no shadow line, even with `ticket` in `config/machine-enforce`, while an unlisted illegal pair is still refused; and `bin/jg-machine.sh reconcile ticket` lists each observed edge with its count, writer and verdict and exits 1 on a real edge nobody names (`bash tests/jg-machine-ticket.test.sh`, case 9).
