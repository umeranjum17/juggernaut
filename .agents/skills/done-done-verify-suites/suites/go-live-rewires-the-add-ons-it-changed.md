# Go-live rewires the add-ons it changed

Go-live rewires the add-ons it changed: run `done-done run -- bash -c 'bash tests/jg-update-local-base.test.sh && bash tests/jg-host-wiring.test.sh && bash core/pipeline-quota-failover/tests/pipeline-quota-failover-uninstall.test.sh && bash core/claude-accounts/tests/claude-accounts-pick.test.sh && bash tests/jg-home-guard.test.sh && bash tests/jg-trunk.test.sh'` (screen: none); a fixture trunk carries the real `bin/jg-host-wiring.sh` and the real `core/tickets-sync`, every other step a logging stub, and `bin/jg-update.sh --base` moves a lead and Main in a throwaway user home: the first move wires every step and records `state/host-wiring.tsv`, a move that changes `core/tickets-sync/sync.py` wires only tickets-sync and its installed copy equals `core/`, a move that changes no add-on file runs no wiring, a failing step is named in the row as `live,wiring-failed:<step>` and retried on the next move, and a home whose health check rolls it back onto the moved commit is still wired to the code it holds.
A pipeline config that names the pre-rename `fm-pipeline-quota-failover` wrapper is moved to the current wrapper by the real step and every home ends `live`, a rerun changes nothing and a foreign wrapper is still refused; an account-pool file naming the pre-rename add-on chooser is adopted the same way.
A home whose shared reference-transaction hook is the trunk guard moves and stays `live`, because the home guard chains the trunk guard (both still refuse, a rerun and a landing change neither hook); any other hook refuses the guard install and the `rolled-back:missing-guard` row names that refusal.
