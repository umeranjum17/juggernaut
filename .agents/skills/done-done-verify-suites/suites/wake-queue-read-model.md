# Wake queue read model (Go)

Wake queue read model (Go): run `bash tests/jg-wake-core.test.sh` (or `done-done run -- bash tests/jg-wake-core.test.sh` with the suite's log written into `$DONE_DONE_EVIDENCE_ROOT`); it sources `bin/jg-wake-lib.sh`, which forwards the queue readers to `core/wake/cmd/jg-wake-core` through `bin/jg-wake-core.sh`, and proves the deduped rows, the keys queued for a kind, which sequence numbers are still queued, the per-actor pending count over a live branch grant, and that a grant row-list must be distinct numbers, all against the shell's recorded answers (`tests/fixtures/wake-recorded/queue-reads.tsv`). For a port or change of those readers, replay the shell at the base commit against the Go command over every recorded queue row and the shapes the stream lacks, with a corrupted control that must differ (`tests/jg-wake-core.test.sh --replay <git-ref>`; `core/wake/README.md` names the replay). Live: `bash tests/jg-wake-queue-live.test.sh` raises one real wake on a throwaway server and reads and withdraws it through the Go path; on a home, `JG_HOME=<home> bin/jg-wake-core.sh --queue <home>/state/.wake-queue dedupe <home>/state/.wake-queue` prints the rows the drain presents (screen: none).
The same live suite also proves a 135569-byte tickets-stale event reaches the real producer, router, bus and durable outbox with complete bytes, owner and identity; a killed render then recovers exactly once, and urgent re-alerts and settled events keep their classes.
`JG_WAKE_PAYLOAD_ONLY=1 bash tests/jg-wake-queue-live.test.sh` selects that journey.
The full live suite also proves 24 sequential and 24 concurrent raises preserve their durable order through offline replay, including migration from an event ahead of the current clock; `tests/jg-wake-daemon-lifecycle-e2e.test.sh` re-enters its real journey with inherited sentinel owner paths and proves the shared wake fixture removes them before the child runs.
