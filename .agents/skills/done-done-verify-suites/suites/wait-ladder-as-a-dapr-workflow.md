# Wait ladder as a Dapr workflow

Wait ladder as a Dapr workflow: run `done-done run dapr-workflow` (`bash journeys/dapr-workflow.sh`, which runs `tests/jg-dapr-workflow.test.sh`); in a throwaway home on free ports it starts a real scheduler, sidecar and worker with `bin/jg-dapr-workflow.sh up`, schedules a wait episode with a 2s owner timer and a 4s escalation timer, and proves each rung fires on its real timer (the log prints the measured seconds) and queues one wake, a cleared episode delivers nothing, and recorded waits (`tests/fixtures/escalation-waits/waits.tsv`) prove the five escalation rules from `core/bus/workflows/escalation-optimization.json` (a silent wait wakes nobody, a security wait ignores a spent budget, 2 of 3 waits wake on a 2-wake budget, three grouped waits leave as one digest, re-alert gaps double up to the cap, and a wait whose lane status changed closes with no wake), and `install` writes the detached argv as units, refuses another home's units and touches only a stub service manager. It skips with a named reason when Go, daprd or the pinned scheduler release are unavailable. Never run `bin/jg-dapr-workflow.sh install` against the live home from a worker: only the primary home's owner path installs the service.
