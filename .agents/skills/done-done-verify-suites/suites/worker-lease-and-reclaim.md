# Worker lease, heartbeat and reclaim

Worker lease, heartbeat and reclaim: run `done-done run -- bash -c 'set -e; printf "{\"target\":{\"version\":\"juggernaut\"},\"start\":\"a fixture home with a real Beads store, rows owned by live panes, a done lane with an exited pane and a row no task record holds\",\"steps\":[\"start the rows so they take a lease\",\"run the delivery tick every 30 s and then every 60 s for 6 minutes with 22 live panes\",\"put a ticket on hold and release it\",\"let a done lane pane exit past the grace time\",\"let an unheld row run past the grace time and start it fresh\"],\"result\":\"no live lease lapses, a heartbeat leaves the changes read empty, a held ticket raises no alarm, a lane with a record is not reclaimed or relaunched, an unheld row returns to ready naming who lost it and a fresh start takes it\"}" > "$DONE_DONE_EVIDENCE_ROOT/steps.json"; bash tests/jg-lease-tick.test.sh > "$DONE_DONE_EVIDENCE_ROOT/lease-tick.log" 2>&1'` with `JG_BEADS_TEST_BD` and `JG_BEADS_TEST_DOLT` naming the pinned builds; on a real store the delivery tick (`bin/jg-lease-tick.sh`) sends each live worker's heartbeat as its agent name every 120 s, at most 20 a pass and the longest-waiting first, so a 300 s lease never lapses with the watcher's 30 s tick or the sentinel's 60 s tick alone; a heartbeat changes no row and no history line; a held ticket raises no alarm and takes a new lease after the hold; a row whose lane has a task record keeps its owner whatever its pane does and nothing is relaunched; only a row in progress with no task record and a lease 10 minutes past returns to ready (`config/lease-reclaim` reading `report` only says so), the line names who lost it, and a fresh start takes the row.
