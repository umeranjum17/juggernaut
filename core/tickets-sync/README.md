# Tickets sync

Run `JG_HOME=<fleet-home> bash tickets-sync/wiring.sh` from merged main to register the existing watcher's poll; `--dry-run` writes nothing.
Requires Python 3.11+, gh-axi, tasks-axi, sign-off-axi 0.9.10+ and Juggernaut's backlog libraries; the board comes from `config/fleet-board`.
Backlogs stay read-only: archive headings are normalized in retained copies under `state/tickets-sync/` before tasks-axi reads them.
Open work and seven days of completed work are backfilled by stable home/item hashes; lane status and linked GitHub PR state supply queued (0), building (30), review/CI (65), merging (90), and done (100) progress, plus the matching `--stage` word and `--last-event-at` from the newest status `[at=]` stamp or the start of the backlog created/closed day (omitted when unknown). A backlog record carries a date and no time, so the day's first hour is the only stamp it can honestly claim: a later hour would sit in the future and hold off the board's six-hour stall line by that much, which is how a queued item with no worker showed nothing but 0% for fifteen hours.
Parked homes and held items stay On hold, always with the reason the board needs: the item's own `hold_reason`, or the parking that holds a whole home; completion clears hold.
Confirmed `parent: <item id>` wins even for captain-tagged work.
Unparented captain asks are roots, titled with their stored quote or plain recorded title; other work joins a unique same-project ask sharing a specific brief phrase, or the single fleet-wide `Not from your asks (fleet upkeep)` root.
Legacy placeholder records move under that root as earlier grouping history; internal home names are cleared from project fields.
Each poll uses a field-hash ledger and a 20-second cursor budget; mid-pass continue notes go to `state/tickets-sync/progress.log` (check stdout wakes Main). A finished pass with changes prints one summary; one ticket the board refuses prints a single `tickets-sync: skipped <id>: <home>/<item>: <reason>` line and the rest of the pass still runs; failures that stop the pass print on stderr. `sync.py --audit` runs the full ticket list separately.
Every ticket line carries an `assignee` the board shows, built from this home's own records and never typed, and it is never blank: `lead` is the owning lead the record names, else the home that owns the item, so fleet-wide work with no owning lead still says who answers for it. From the lane meta, whether a worker is live or the last one has gone, it also carries `model`, `tool` (the board's word for the record's `harness`) and `effort`, and the `account` it runs under as both `account` and the `worker` the board draws, with `worker_id` naming that run; `live` says whether one is running now. An item that has not started and holds no record of a worker says `no worker yet` in those fields instead of leaving them empty, while an item that has started, or one whose record cleanup has already removed, says nothing rather than claiming no worker ran. A board that still shows a row the poll published before it re-keyed its ids (`fm-<hash>` beside `jg-<hash>`, the same work) gets the same owner on that row too, and a row whose work another ticket already covers still names its owner: on both only the assignee is written, and nothing else on them moves. sign-off's writer takes no assignee field, so the poll appends that line itself, in the shape the feed's format lets another program write, as the whole ticket record: every other field keeps its name, type and meaning, and a feed from an older version still reads.
Public titles cap at 160 characters and omit bookkeeping tags, priority prefixes and URLs; release and delivery PR use their own ticket fields.
Full request context is cached by source-file revision so truncated list bodies cannot hide a confirmed parent; the watcher budget also covers filling this cache.
Each real project name gets its local image (`core/tickets-sync/icons`, plus the ten project images still under `addons/tickets-sync/icons` because the one-repo fold's image slice is deferred behind design sign-off; that slice moves the ten and deletes `addons/docs/media`'s two catalog logos) through `sign-off-axi project --icon`, only when it passes `identify` or the XML parser and the registry hash differs; missing or broken images are recorded in `state/tickets-sync/icons-skipped.json` without printing (check stdout wakes Main). Internal homes (`main`, `juggernaut`, `herdr`, …) never become ticket projects.
Backlog completion, merged delivery PRs, and explicit `status: superseded|cancelled` notes or terminal lane events close tickets; URLs in free-form notes do not imply completion.
Use `sync.py --reconcile` to finish every registered home without the watcher budget; GitHub failures name their cause and stop the sync, and open PR state is refreshed after five minutes.
For an authorized board-only cancellation or supersession, use `sync.py --close HOME/ITEM --reason superseded|cancelled --reconcile`; the decision is retained in the sync state's `closures.json`, without editing the source backlog.
Explicit board completion survives a sync-state reset so a stale backlog cannot reopen cancelled work.
Grouping records publish zero raw progress; sign-off still derives their roll-up from children and owns hiding group percentages, collapsed placement, stage words and stale-event age.

## Writing a ticket at the moment it changes

The poll is a backstop, not the only writer. Juggernaut's lifecycle calls `bin/jg-ticket.sh <task-id> [--stage W] [--state W] [--pr URL] [--release TEXT] [--hold-reason TEXT]` at dispatch (`building`), merge (`done` plus the delivered PR), cleanup (the retained PR) and a release cut; the fork-side shim validates the task, then hands `ticket.py` this home so the writer reads the same `config/fleet-board` the poll does.

Every backlog transition writes its ticket in the same step that moves the row, through `jg_backlog_ticket_note` in `bin/jg-backlog-transition-lib.sh`: `start` is `building` and in progress, `done` is `done` at 100% with the delivered PR `--pr` names, `reopen` returns it to queued, and a hold or a release carries the hold with its reason. `bin/jg-tasks-axi.sh` calls the same helper after its own `start`, `done`, `reopen`, `hold`, `park` and `unhold`, and `bin/jg-captain-hold.sh` after it holds, releases or closes a captain call, so the board follows the work whichever path moved it and no sync run is needed to catch up.

`ticket.py` corrects an existing ticket in place: it writes only the fields that differ, so a repeated step appends nothing; `--state done` also sets 100%; it deliberately leaves `last-event-at` to the poll, which derives it from the real status stamps. A hold travels with the state, because the board refuses a ticket held for no reason: `--state "on hold"` needs `--hold-reason <why it waits>` and writes nothing without one, and any other state releases a hold the row still carries. It never creates a ticket — the poll owns titles, parents and the ask a ticket answers — so writing for a task with no published ticket, an absent writer, or a home with no fleet board is a silent no-op that exits 0. A real failure names its cause on stderr and exits 1, and every caller guards the call, so a board problem never fails a merge, a dispatch or a cleanup.

To cut a release, call the same shim with `--release <name>` for each ticket the release ships.

## The checks

`state/tickets-sync.check.sh` runs the poll; `state/tickets-stale.check.sh` runs `sync.py --check`. The second one reads every registered home and prints one line for each ticket whose state contradicts its own work — the board still says queued or in progress while the backlog item is closed and its PR merged, or the reverse — and for each `jg-` ticket left on the board that no home's work accounts for. It writes nothing, and silence means the board is true. A row whose work another ticket already covers is left alone on purpose, so it is not reported as a contradiction.

Both are registered as Juggernaut checks and both are classified `batch` in `defaults/wake-routing`: a report of settled or surplus board rows is bookkeeping, not a decision, so it arrives with the next wake of any kind or with the queue-resurface cadence and never costs a turn of its own. `docs/watcher-continuity.md` ("Wake urgency classes") owns the classes and a home's `config/wake-routing` override.

The `--reconcile` backfill reads a truncated row's full record side by side with the other rows, so one pass finishes the cache a check would otherwise fill a budget at a time; a merged or closed PR is remembered instead of re-read every five minutes; and only rows the pass can publish, rows another row names as its parent, and request rows with no parent are read at all. On this home's real 4,339-ticket board that is 21 seconds from a cold read cache and under a second warm, against a 20-second watcher budget the check now finishes inside; a one-off backfill of 413 rows the board had drifted on took 122 seconds, because each corrected row is one sign-off write.

## The daily clean-up

`state/tickets-cleanup.check.sh` runs `sync.py --cleanup`, which reads like `--check` and acts once per UTC day. It flags duplicates, still-open superseded tickets, P0/P1 tickets quiet for 14 days, holds with no `until:`, `trigger:` or `resume:` note, and open tickets in parked projects. A captain-ask ticket must carry his quoted words, `quoted-at:` and `source:` in its note; when only the date or link is missing, the clean-up finds the quote in a `state/*.inbox` steer record and writes both back with `jg-tasks-axi.sh update`, and when no record holds it the ticket is flagged `no-source`. Everything flagged becomes one `ticket-cleanup-<day>` keep/remove card whose detail holds the findings that fit sign-off's 1000-character cap and ends `... and N more`, the complete list goes to `state/tickets-sync/cleanup-<day>.txt` that the printed line names, and the check prints one line. A merge or split keeps every quote on the surviving ticket. The board's open view (sign-off's Asked block) shows the title and filed date of the earliest ask card whose `ticket` names the ticket, so a captain ticket with no such card is flagged `no-ask-card`; the clean-up cannot raise the card itself because sign-off holds card titles to a question of 12 words.

### Card reconcile

The same daily pass reads every waiting sign-off card that asks for an answer (a card with buttons, or a sign-in) and checks its source with read-only calls; `reconcile.py` owns the rules. It archives with `sign-off-axi dismiss <card> --reason ...` only on clear evidence: the card's `ticket` is done, or the backlog item named by `ask_ref` or by the `fm-<hash>-<task>-<stamp>` key is closed or no longer held (`done-elsewhere`); every GitHub PR the card links is merged (`done-elsewhere`) or closed (`not-relevant`); a sign-in link has expired (`not-relevant`); or a newer card asks the same title (`replaced`). A card with an open ticket, held task or open PR is kept. A card that holds the captain's own words is archived only on the first two or the PR evidence, never on the weaker expiry or duplicate signals. Each dismissal is one line in `state/tickets-sync/card-reconcile.log`. Cards it cannot judge stay; the check prints them under the summary line (first eight) and `state/tickets-sync/cards-unclear.txt` holds all of them, for Main to settle.
